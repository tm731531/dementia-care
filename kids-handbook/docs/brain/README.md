## 為什麼有這個資料夾

`00-spirit.md` 講核心、`03-school-age-6-15-ai.md` 講 frame、`04-cross-stage/four-firewalls/` 講方法 ——

這裡是累積場景的地方。

---

## 怎麼寫

**檔名：`YYYY-MM-DD.md`**（一週一個切片）

範本：

```markdown
# 2026-05-29 週紀錄

## 這禮拜的場景

### 場景 1
- 她問了什麼 / 做了什麼：
- 我（或太太）怎麼回應：
- 事後想：我替她做了？還是讓她做？

### 場景 2
...

## 對應到 4 層 firewall

| 場景 | 對應的 firewall | 我做得怎樣 |
|------|----------------|-----------|
| 場景 1 | baseline | □ 好 / □ 差 / □ 沒注意 |
| 場景 2 | ownership | □ 好 / □ 差 / □ 沒注意 |

## 這禮拜的反省

- 哪個瞬間「我幫她做比較快」我忍住了：
- 哪個瞬間我替她做了，下次怎麼修正：
- 太太處理 vs 我處理有什麼差異：

## 給未來的我

（給下個月的自己留訊息）
```

---

## 怎麼用標籤

每個場景可以標籤 5 類：

| 標籤 | 意思 |
|------|------|
| `baseline` | 她在累積某個動手領域的熟度 |
| `order-lock` | 知識來源的順序問題 |
| `describe` | 她在練結構化描述 |
| `firewall` | 我們在當 firewall（暫時的） |
| `ownership` | 她在 own 她的問題 |

每月 [`../skill/`](../skill/) 對齊時看這禮拜哪些標籤多 / 哪些缺。

---

## 不要做的事

- ❌ 不要等到「我有時間寫詳細的」才寫 —— 一句話也行
- ❌ 不要寫成「教養紀錄」給別人看 —— 這是給你跟太太內部對齊用的
- ❌ 不要請 AI 寫具體場景 —— 違反 ownership 精神
- ❌ 不要因為「這禮拜沒事可寫」就空白 —— 反思「為什麼這禮拜沒場景」本身就是 data

## 隱私

這個資料夾的內容是 **家庭內部紀錄**，不上傳 GitHub Pages（GitHub Pages 部署只發佈 `index.html`，docs/ 不自動發佈）。

但既然 repo 是 public，如果你不想 brain/ 內容被推上 GitHub：

選項 A：在 monorepo root 的 `.gitignore` 加 `kids-handbook/docs/brain/*.md`（除 README.md）
選項 B：brain/ 內容只放 local，每月對齊後把 skill 結論寫到 [`../skill/`](../skill/)

選擇權在你跟太太。
