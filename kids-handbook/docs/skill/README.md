# skill/ — 對齊後的家庭做法

> 你跟太太每月對齊一次，把「這個月確認 work 的做法」寫進來。

---

## 跟 brain/ 的差別

- [`../brain/`](../brain/) = **原始紀錄**（場景 + 即時反應）
- skill/ = **對齊結論**（你跟太太討論後確認的做法）

brain/ 是 raw data，skill/ 是 processed wisdom。

---

## 怎麼寫

**檔名：自由命名**（按主題，不按時間）

範例：
- `bedtime-routine.md` —— 睡前怎麼處理「她不想睡」
- `dispute-with-classmate.md` —— 她跟同學吵架時怎麼引導
- `screen-time-rule.md` —— 螢幕時間規則
- `unknown-person-asking.md` —— 陌生人問問題怎麼回（程序性 firewall）
- `frustrating-task.md` —— 她做事卡關時你怎麼接

範本：

```markdown
# {{主題}}

## 觸發場景
（什麼情況會用到這個做法）

## 我們對齊的做法
（你跟太太討論後確認的具體 step）

## 為什麼這樣做
（對應到哪層 firewall / 哪個 ownership 原則）

## 怎麼判斷在 work
（什麼訊號表示她在長 ownership / 什麼訊號表示我們替她做太多）

## 更新歷史
- YYYY-MM-DD：建立
- YYYY-MM-DD：修正（因為 ______）
```

---

## 對齊的時機

- **每月一次**：固定時間（例：每月最後一個週日晚上），你跟太太一起翻 [`../brain/`](../brain/)
- **重大事件後**：踩到大坑 / 大進展時臨時對齊
- **發現「我們兩個處理方式不一樣」**：這時候 Sam 要對齊不然孩子 confused

---

## 不要做的事

- ❌ 不要從別人家抄做法 —— 一抄就失去 ownership 精神
- ❌ 不要寫成 SOP（「步驟 1 / 步驟 2 / 步驟 3」）—— 這是方法論不是流程
- ❌ 不要追求每個月都產出 skill —— 沒對齊到的事就空白，比硬生不出來真實
