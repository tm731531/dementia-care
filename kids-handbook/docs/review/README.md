# review/ — 月年回顧

> 每月 + 每年看 ownership 的成長軌跡。

---

## 月 review

**檔名：`YYYY-MM.md`**

範本：

```markdown

| 標籤 | 次數 |
|------|------|
| baseline | |
| order-lock | |
| describe | |
| firewall | |
| ownership | |

某個標籤特別多 / 特別少代表什麼？

## 這個月確認下來的做法（搬到 skill/）

- [ ] 主題 1（連結）
- [ ] 主題 2

## 她的 ownership 成長軌跡

（這個月觀察到她「自己想」的瞬間 —— 不是技能進步，是 ownership 的訊號）

- 例：5/12 她問「為什麼天空是藍的」之後 **沒等我回答** 自己跑去看書找答案 → ownership 在長

## 下個月聚焦在哪

（這個月發現薄弱的 firewall 層，下個月加強什麼）
```

## 年 review

**檔名：`YYYY.md`**

範本：

```markdown
# 2026 年回顧

## 她長出來的 ownership

（具體場景 + 證據，不是 vague「她長大了」）

## 我跟太太拆掉的 scaffolding

哪些 firewall 我們從「主動當」變成「被動 standby」：
- [ ] 例：以前她不知道時直接給答案 → 今年改成「你覺得呢？」

## 還沒做好的

- [ ] 哪一層 firewall 還薄弱
- [ ] 哪些場景我們還是「幫她做比較快」

## 我跟太太的協作品質

（不是孩子的事，是我們兩個對齊得怎樣）
- 我們處理同樣場景的差異：
- 我們對齊頻率夠不夠：

## 下一年的 1 個重點

（不是清單，是 1 個 —— 多了會分散）
```

---

## 為什麼分月跟年

- **月**：data quality 還在，記得清楚。看的是 firewall 跟做法是否 work
- **年**：拉遠看 ownership 軌跡。看的是「她變成什麼樣的人」這個更長線的問題

---

## 不要做的事

- ❌ 不要看數字進步（這個月做了 X 件事）—— 看 ownership 質地
- ❌ 不要跟別人家比較
- ❌ 不要把 review 變成「家長自評」—— 重點是看她的長大，不是檢討我們
