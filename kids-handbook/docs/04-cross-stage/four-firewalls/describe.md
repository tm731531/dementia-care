# 04-2-3 · Firewall 3 — 結構化描述（輸入端有自覺）

> 解決的擔憂：**AI 給的答案是 generic 的，context 被拿掉了。孩子直接套用 → 踩坑，而且不知道為什麼踩。**

---

## 核心 frame

布林通道的例子：

- AI 給「80/20 策略」 —— generic，但 boundary 被拿掉
- 適合大盤 / 週期性股，不適合個股
- 孩子套用 → 踩坑 → **不知道為什麼踩**

「不知道為什麼踩」比踩坑更可怕，會導致：
- 怪 AI（騙我）
- 怪自己（不適合）
- 怪運氣
- 全部不信任 → 虛無

---

## 對比 Tom 自己

你 AP 層 vs SQL 層那次能歸因，是因為 **你知道自己在做什麼**：

- 你寫了 AP 層 code → 知道你在 AP 層
- 你看到 query 時間數字 → 有可量化的訊號
- 失敗後你能拆「哦原來這層做會慢」

孩子拿 AI 的策略就用，他 **根本不知道自己在做什麼**（他只是執行）。失敗了 **沒有任何資料可以拆** —— black box 進、black box 出。

→ 問題不是「驗證輸出」，是 **「輸入端要有自覺」**。

---

## 具體做法

**在用 AI 之前，她要會描述：**

> 「我有 X、我看到 Y、我想達到 Z、我預期 W 會發生。」

有這個描述：
- 才能 **正確問 AI**（AI 答案的品質取決於 prompt 品質）
- 才能 **事後歸因**（我哪個前提錯了）

---

## 怎麼練（不是教，是浸泡）

這個能力不能等到要投資 / 做大事才練。要從**小事**練起：

| 場景 | 練什麼 |
|------|--------|
| 描述今天為什麼跟同學吵架 | 不是情緒，是事件 + 期待 + 落差 |
| 描述一個玩具壞掉的原因 | 前提、行為、結果 |
| 描述一次出遊「預期 X、結果 Y」 | 預期 vs 實際差在哪 |
| 描述為什麼喜歡某個食物 | 把模糊感覺結構化 |

**最強的學習途徑是模仿。**

**你跟太太自己決策時出聲想**（「我們以為這家餐廳會好吃 → 結果不好吃 → 下次怎麼判斷？」），孩子會把「歸因」當空氣吸進去。**她那個能力不是教出來的，是聽你們講出來的。**

---

## 性質

- describe 是 **輸入端**（problem framing）
- verify 是 **輸出端**（answer checking）
- 兩個是不同方向的肌肉

AI 時代 verify 越來越難（環境不允許），但 describe 反而越來越重要（沒人會替你 frame 問題）。
