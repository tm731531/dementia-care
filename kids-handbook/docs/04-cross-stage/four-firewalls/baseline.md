# 04-2-1 · Firewall 1 — Baseline（熟到無聊）

> 解決的擔憂：**AI 把所有事都做到「夠好」這個程度，孩子永遠不會深入一件事到習慣，也就永遠 build 不出 baseline。沒有 baseline，後面整條好奇心機制都不會啟動。**

---

## 核心 frame

Tom 自己當年的「SQL 比 AP 層快」覺醒，能發生是因為：

1. 在原公司做 C#+jQuery 做了 2 年 → **建立了 baseline**
2. 換公司接觸 SQL → **驚奇 / 偏差**
3. 自己看 query 時間數字 → **客觀訊號**

| 元素 | 你當年 | 小孩 |
|------|--------|------|
| baseline | 在原公司待 2 年做到習慣 | 沒有 —— 沒做過任何一件事到「習慣」的程度 |
| 驚奇 / 偏差 | SQL 居然能更快做掉 AP 層的事 | 沒 baseline 就沒「咦」 |
| 訊號 | $（薪水）+ 時間（更快） | 沒有 $；有的是身體訊號：行/不行、快/慢、卡/不卡 |

AI 不是搶走答案，是 **搶走「枯燥到習慣」那段時間**。

---

## 具體做法

**保護 1-2 個「她可以完整 own + 動手 + AI 介入不了」的領域。**

候選領域（純舉例，請你跟太太挑你家做得到的）：

- 種植物 / 種菜（你已有 `garden-handbook` 當素材）
- 養活的生物（魚、蝦、蠶、烏龜）—— 死了就是死了，AI 救不回來
- 烹飪（從生到熟，火、刀、調味，全部物理訊號）
- 修補（玩具、腳踏車、衣服）
- 樂器或某項運動（重複 → 身體訊號 → 可衡量進步）

這個循環要保護的是：**baseline → 動手 → 預期 → 驗證 → 修正**

---

## 性質

- AI 介入不了
- 父母也代勞不了（代勞就沒有身體訊號）
- 失敗有真實後果（魚會死、菜會枯、麵會燒焦）
- 重複到「熟到無聊」是 feature 不是 bug

---

## 失敗訊號

- 她對「為什麼」沒興趣只想要「答案」 → baseline 沒建立或被 AI 吃掉
- 她對任何事都「興趣 3 天就過」 → 還沒進入「熟到無聊」的階段就被拉走
- 她沒有「我親手做過」的事可以講 → baseline 領域沒長出來
